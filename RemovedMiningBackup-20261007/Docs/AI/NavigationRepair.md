# Miner / ore navigation repair

The movement authority remains Terrain A* plus a Rigidbody motor. No NavMeshAgent or reactive static-obstacle steering has been added.

## Responsibilities

- Ore hit feedback animates a separate mesh-only visual pivot. Gameplay colliders stay anchored. Depletion removes collision before the cosmetic break animation finishes.
- Ore spawning validates inactive, finally rotated/scaled collider bounds, nine support samples, spawn bounds and footprint clearance. A rejected candidate is returned to the pool; it is never activated in an unsafe position.
- Miner spawning uses the scaled capsule profile and a supported, clear grounded position. Restoring a saved population waits for navigation/space instead of silently losing miners. Failed purchases retain the existing refund behavior.
- MiningNavGrid accepts per-request profiles, shares the same capsule checks across graph edges, smoothing and the motor, and budgets dirty updates independently from round-robin searches. Disabled grids cancel requests; stale generations cannot install routes. Searches can survive unrelated topology changes; the entire output route is validated against current geometry before delivery and stamped with that revision.
- Shared stand leases own actual destinations across neighboring mineables. Automatic ore selection prefers unclaimed mining capacity before saturated targets. Active capacity is separate from FIFO waiting positions. Holders seek space outside other workers' mining approach lanes, searching local rings away from their target before using ore-centered fallback rings. Lease spacing includes arrival tolerance so separately reserved miners cannot settle overlapping. Arrived holders stop requesting paths to their own position. A miner must arrive at its stand point before mining, and impact events recheck range.
- The follower reanchors asynchronous results to the current position, skips only genuinely passed intermediate corners, looks ahead through clear corridors, and brakes by remaining route distance. Long corridor visibility checks are cached for `NpcData.RouteValidationInterval` (default 0.2 seconds), invalidated immediately by topology/corner changes. The look-ahead point itself is recomputed from the current actor position every tick, including at upgraded speeds. The actual motor capsule and next physics step are still checked every tick.
- Miner route requests snapshot stationary mining/holding workers as occupied discs. Graph edges, smoothing, live reanchoring and follower look-ahead all respect them, so a retry cannot choose the same corridor through a parked worker. Moving traffic remains the crowd solver's responsibility; monster target-approach searches retain their existing actor rules.
- The crowd coordinator solves reciprocal velocity constraints from a physics-tick snapshot, with spatial buckets and a final paired next-step separation check. Narrow corridor FIFO claims apply only to opposing traffic with a clear connection; parallel and wall-separated lanes do not share an exclusive claim. A stalled claim holder rotates to the back rather than renewing ownership indefinitely. It does not change the static route.
- If parked workers seal a route, a second static-only search runs within the same bounded search budget. Its `Crowded` result is an access request, **not** a successful movement route. Stand ownership asks one blocking parked worker to yield through the normal safe holding allocator. The requested corridor remains excluded from that worker's holding choices even when the requester is walking to another waiting slot. `NpcData.CrowdYieldDuration` defaults to a minimum of 3 seconds, with a cooldown and holding-arrival requirement. The blocker cannot return until the requester passes, parks at its destination, changes destination or disappears. The requester keeps its stand goal stable while access is pending; `NpcData.CrowdAccessTimeout` (15 seconds) still permits bounded recovery when clearance cannot be granted. Sealed static geometry remains unreachable; neither path installation nor motor collision is bypassed.
- Static cell/corridor clearance is shared by exact actor radius/height and invalidated when obstacles change. Direct safe routes avoid A* expansion. New request admission, search expansion and stand allocation all have separate bounded quotas. Stand orientation initially prefers the worker's approach side and remains stable for its lease lifetime. Existing waiting leases are checked again when new mining approaches cross their space. An already-overlapping crowd clearance margin permits only monotonically outward movement; the motor's static and paired collision checks still apply.
- Recovery distinguishes grid/path/slot waiting, useful route progress, crowd yielding, invalid placement and unreachable targets. A path-service watchdog defaults to 5 seconds, checks that the backend is still processing work, and excludes intentional rune freezes. Queue age alone does not restart a healthy request at the tail of the queue. Invalid-placement recovery only accepts connectors that do not increase penetration against any initial blocker or introduce a new blocker. The motor separately validates the actual capsule pose rather than silently projecting an invalid start above a wall.

## Unity configuration

- New grids default to 0.5 m cells. Existing serialized values are retained.
- `MiningNavMeshBuilder.useSurfaceBounds` is opt-in: the bounds must include monster entry/spawn paths, not just the mining field. Leave it off for existing Terrain-wide navigation.
- Terrain is sampled for height/slope/holes. Non-Terrain floors and platforms must use the project's Ground layer when it exists; walls and ore must not use that support layer. Use explicit support/blocker masks when authoring non-Terrain maps.
- Miner capsules get a shared zero-friction, zero-bounce physics material. Do not enable contact pushing between miners; crowd separation is authoritative.
- Keep ore collision geometry outside animated ancestors. Existing mesh+collider prefabs are adapted at runtime without moving the collider or replacing its references. An authored collider-free visual child may be assigned to `visualPivot`.
- Legacy ore NavMesh carving remains disabled. Rebaking a NavMesh does not fix the active A* grid.
- New crowd/recovery values are editable in NpcData. Save keys, purchases, upgrade values, progression and authored placements are not migrated.

## Diagnostics and validation

Select a miner: cyan capsule, green stand lease / gray waiting lease, magenta preferred velocity, green accepted velocity, state, pending age, remaining route distance and rejection reason.

`Mining Simulator > Validation > Navigation Repair` creates and closes a disposable additive scene. It checks real physics connectivity, wall disconnection/detours, smoothing clearance, out-of-bounds queries, queue progress under dirty work, cancellation/unavailability, re-enable recovery, scaled capsule profiles and inactive rotated footprints. It does not write player saves.

`Assets/NavigationRepairSoak.unity` is an opt-in isolated Play fixture. It has no wallet, shop, progression, quests or save services. It runs 1, 16, 32, 64 and 100 primitive miners for two minutes each. Its synthetic mining event calls test the mining contract, not production animation timing. Read `NavigationRepairSoak.Snapshot()` for state counts, overlap/invalid-placement samples, request ages and frame observations. This is not a before/after performance benchmark.

For a fixed-population ten-minute stress run, call `NavigationRepairSoak.BeginCrowdSoak(100)` after entering the isolated scene. This resets its counters and disables population phases. Never leave `EditorSceneManager.playModeStartScene` set to this fixture: clear the override immediately after entering Play and verify it is null after stopping. The fixture does not set that override itself and is not a production startup scene.

The grid is still a single supported floor per X-Z location. Stacked floors require separate/layered navigation. Sealed targets and saturated fields must wait/retry; no collision bypass is allowed. Production animation-driven mining, monster/chest/lucky-block regression scenarios and comparable baseline performance recordings require separate gameplay validation.
