# Mouse sensitivity and global SFX

- Settings adds an authored Mouse Sensitivity slider, 0.25x-4x by default. Range/default are configurable in MiningGameData. Multiplier applies to mouse delta and angular-speed cap, is stored under MiningSimulator.MouseSensitivity.v1, and is refreshed on all existing orbit rigs. Slider label is localized through English/Vietnamese Lean tables.
- Shift Lock uses an independently editable 720 degrees/second cap and 0.025-second smoothing baseline instead of the exploration 180-degree cap. Both scale with sensitivity. Existing camera collision, framing and free mouse ownership remain unchanged. Current scene character-facing tuning uses 0.08s and 1440 degrees/sec for responsive tracking.
- Reapply authored UI in another checkout using Mining Simulator/Setup/Add Mouse Sensitivity To Settings. It clones only the existing SFX row's skin, clears cloned persistent volume callbacks, fits four rows into the existing 700x650 panel and preserves header/footer/buttons. Scene edits are not auto-saved or included in ZIP.
- MiningAudioManager owns a registry of external SFX channels. Effective gain = Master * SFX * AudioData.SfxVolume, with global mute giving zero. Each source retains its own authored base volume, pitch, clips and spatial settings. Music and manager ambience channels are excluded; existing SFX mixer group is reused if assigned.
- StarterAssets exposes a movement-source-created event, not a dependency on Assembly-CSharp. Audio manager subscribes/unsubscribes and applies settings to footsteps/landing without changing animation events. Authored channels are registered once on manager enable, monster channels when monsters enable, and chest channels at creation/play. New custom runtime SFX sources should call RegisterSfxSource; no per-frame scene search or new sound clips are introduced.
- Attack/draw/sheath/jump/death/exhaustion/drop/loot paths already call PlaySfx and now share the same settings as independent channels. Player save/progression data is untouched.
- Validation: Unity compilation has zero errors after respecting StarterAssets assembly boundaries. Play Mode slider 2x reported a 1440-degree/s Shift Lock limit. Footstep source volume 0.8 -> 0.2 -> 0 at SFX 100%/25%/0%; monster source 0.48 -> 0.12 -> 0. Global mute yielded zero and audio-manager disable/re-enable retained correct 0.12 gain. Original user sensitivity/volume values were restored after tests. Screenshot verified the new Settings row. Existing Missing Script warning remains unrelated. Actual perceived sensitivity/audio loudness needs user playtesting.
